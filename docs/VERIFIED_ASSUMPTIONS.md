## 4. Context Window & Truncation Semantics

Inspected from `laya/common.py` (`build_sequence`) and `laya/agent.py` (`Agent.predict`, `Agent.predict_long`):
- **Base Context Window:** 512 tokens (can support up to 1024 on `laya-typed-decisions`).
- **Head Budget (`head_max_len`):** Default 192 tokens reserved for question instructions and options.
- **State Room:** Only `max_len - head_max_len - 3` tokens (~317 tokens by default) are allocated for the email body.
- **Silent Truncation Hazard:** Standard `Agent.predict()` silently truncates the state text if it exceeds the remaining state room.
- **Verified Long Input Strategy:**
  - For emails exceeding token limits, we use sliding-window chunking via `Agent.predict_long` or bounded structured summaries.
  - Aggregation rules:
    - `noul` (boolean): $P(\text{true}) = \max(\text{windows})$ (a threat in any window flags the threat).
    - `choice` & `score`: Selected from the highest-confidence window.
  - **Requirement:** Any chunking or windowing **must be explicitly recorded** in `limitations[]` or metadata; silent truncation is forbidden.

## 5. Question Specification and Head Limits

Inspected from `laya/presets.py` and `laya/common.py`:
- Supported primitives:
  1. `choice`: Dict of string keys to descriptive criteria strings (e.g. `{"phishing": "credential harvesting or spoofing", "legitimate": "normal correspondence"}`). Note: Options share a 256-token head budget; keep options $\le 20$.
  2. `noul`: Boolean assertion returning calibrated $P(\text{true})$ and $P(\text{false})$.
  3. `score`: Ordered list of rubrics or integer scales.
- Question configuration must reside in a versioned configuration file (e.g. `config/laya_questions.v1.json`).
